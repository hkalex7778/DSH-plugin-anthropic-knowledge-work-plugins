# /capacity-plan — 团队产能规划

> Modified from the original work by Anthropic.
> 移植自 anthropics/knowledge-work-plugins (operations 插件, Apache-2.0)，正文已中文化并适配 DeepSeek Harness 工具。

分析团队产能并给出资源分配方案。核心是回答三个问题：现在人够不够、缺口在哪、怎么办。

## 我需要你提供

信息不全时先用 `ask_user_question` 一次问清（不要连环追问）：

- **团队规模与角色**：都有哪些人、各自职责。
- **当前工作负荷**：现在在做什么（可从项目跟踪工具导出，或直接描述/粘贴）。
- **接下来的工作**：下个季度有哪些事。
- **约束条件**：预算、招聘时间线、技能要求。

## 三个规划维度

### 人
- 可用编制与技能
- 当前分配与利用率
- 计划招聘与到岗时间
- 外包与供应商产能

### 预算
- 按类别的运营预算
- 项目专项预算
- 偏差跟踪
- 预测 vs 实际

### 时间
- 项目时间线与依赖
- 关键路径分析
- 缓冲与应急预留
- 交付节点管理

## 利用率目标

| 角色类型 | 目标利用率 | 说明 |
|-----------|-------------------|-------|
| 执行/专家 | 75-80% | 给响应型工作与成长留余量 |
| 管理者 | 60-70% | 管理开销、会议、1:1 |
| 值班/支持 | 50-60% | 被打断的工作不可预测 |

## 常见坑

- 按 100% 利用率排计划（没有应对意外的缓冲）
- 忽略会议负荷与上下文切换成本
- 没算休假、法定节假日、病假
- 把所有工时等同看待（创造性工作 ≠ 行政工作）

## 连接器（可选）

若已连接**项目跟踪工具**（如 Asana / Jira）：可自动拉取当前工作负荷与工单分配，展示每人下个迭代/季度的承诺。

若已连接**日历**：可把休假、节假日、例行会议负荷算进来，算出每人真实可用工时。
此步需在 设置 → MCP 连接对应日历服务；**未连接时改为手动提供内容**——你直接把每人休假与会议安排贴进来或口述，本技能照常完成产能测算，主体功能不受影响。

## 提示

1. **把所有工作算进去** —— 日常运维、项目、支持、会议。人不可能 100% 投入项目。
2. **留缓冲** —— 目标 80% 利用率。100% 意味着没有应对意外的余地。
3. **定期更新** —— 产能计划很快过期，建议每月复盘一次。
