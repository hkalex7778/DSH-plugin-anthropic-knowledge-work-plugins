# 启动命令

> 如果遇到不认识的占位符，或想确认哪些工具已连接，见下方「⚠️ 连接器依赖」。

初始化任务系统和记忆系统，然后打开统一看板。

## ⚠️ 连接器依赖

本技能可能用到这些服务（按步骤标注）：

| 服务 | 用在哪一步 | 未连接时怎么办 |
|---|---|---|
| **Notion** | 第 5 步：从知识库/笔记里读任务清单 | 改为用户手动贴任务内容，或只从本地 `TASKS.md` / todo 文件引导 |
| **Asana / Linear / Jira(Atlassian)** | 第 5 步：从项目跟踪工具读任务清单 | 改为用户手动贴任务内容，或改用本地文件；跳过自动拉取 |
| **Google 日历 / Microsoft 365 日历** | 第 6 步：深度扫描里的「会议、参会人」 | 跳过日历部分，只基于用户提供的任务/笔记引导 |

**降级原则：** 未连接任何连接器时，本技能**仍可完整走完**——用「用户本地文件（`TASKS.md`、todo.txt）+ 用户口头/粘贴的信息」作为唯一来源，跳过所有自动拉取步骤即可。第 4、5、7、8 步的核心（建文件、解码速记、写记忆、汇报）**完全不依赖连接器**。

此步需在 设置→MCP 连接 `<服务名>`；未连接时改为手动提供内容/粘贴数据，或跳过此步。

## 指令

### 1. 检查已有什么

检查工作目录下是否存在：

- `TASKS.md` —— 任务清单
- `WORKPLACE.md` —— 工作记忆
- `memory/` —— 深层记忆目录
- `dashboard.html` —— 可视化界面

### 2. 补齐缺失的文件

**如果 `TASKS.md` 不存在：** 用标准模板新建（见 task-management 技能）。放在当前工作目录。

**如果 `dashboard.html` 不存在：** 把它从本技能所在目录的**上级** `assets/` 里复制到当前工作目录（即 `assets/dashboard.html`，`dashboard.html` 与各技能目录平级）。

**如果 `WORKPLACE.md` 和 `memory/` 都不存在：** 这是全新安装——打开看板后，开始下面的记忆引导流程。放在当前工作目录。

### 3. 打开看板

**不要**用 `open` 或 `xdg-open`——在 DSH 里助手跑在沙箱里，shell 的 open 命令到不了用户的浏览器。改为告诉用户：「看板已就绪，在 `dashboard.html`。从文件管理器打开它即可开始。」

### 4. 让用户对齐上下文

如果一切都已初始化过：

```
看板已打开。你的任务和记忆都已加载。
- /update 同步任务并检查记忆
- /update --comprehensive 深度扫描所有活动
```

如果记忆还没引导过，继续第 5 步。

### 5. 引导记忆（仅首次）

**只有在 `WORKPLACE.md` 和 `memory/` 都还不存在时才做这一步。**

职场语言最好的来源是用户真实的任务清单。真实任务 = 真实速记。

**问用户：**

```
你的待办/任务清单放在哪里？可以是：
- 本地文件（如 TASKS.md、todo.txt）
- 一个应用（如 Asana、Linear、Jira、Notion、Todoist）
- 一个笔记文件

我会用你的任务来学习你的职场速记。
```

> **连接器提示：** 如果用户答的是 Asana / Linear / Jira / Notion，此步需在 设置→MCP 连接对应服务；未连接时改为让用户手动粘贴任务内容，或只从本地文件引导，或跳过此步。

**拿到任务清单后：**

对每个任务条目，分析其中可能的速记：

- 可能是绰号的名字
- 缩写或简称
- 项目引用或代号
- 内部术语或行话

**对每一条，交互式解码：**

```
任务：「把 PSR 发给 Todd，关于 Phoenix 的阻塞点」

我看到几个想确认理解的词：

1. **PSR** - 是什么的缩写？
2. **Todd** - Todd 是谁？（全名、职位）
3. **Phoenix** - 是项目代号吗？关于什么？
```

逐条过下去，只问你还没解码过的词。

### 6. 可选的深度扫描

任务清单解码完后，主动提出：

```
要不要我对你的消息、邮件、文档做一次深度扫描？
这会花更长时间，但能建立更丰富的上下文——关于你的人脉、项目、术语。

或者先用现在有的，之后再补充。
```

**如果用户选择深度扫描：**

从可用的 MCP 来源收集数据：

- **聊天：** 最近消息、频道、私信（需连接 Slack）
- **邮件：** 已发消息、收件人（需连接 Gmail / Microsoft 365）
- **文档：** 最近文档、协作者（需连接 Notion / Microsoft 365）
- **日历：** 会议、参会人（需连接 Google 日历 / Microsoft 365）

> **连接器提示：** 以上每类来源此步需在 设置→MCP 连接 `<对应服务>`；未连接时改为手动提供内容/粘贴数据，或跳过该类来源。任一来源缺失都不阻塞——跳过并记录缺口即可。

把找到的人物、项目、术语整理成一份脑图。按置信度分组呈现：

- **可直接添加**（高置信）—— 提出直接加入
- **需要澄清** —— 问用户
- **低频/不清晰** —— 记下来以后再说

### 7. 写记忆文件

从收集到的一切，创建：

**`WORKPLACE.md`**（工作记忆，约 50-80 行）：

```markdown
# Memory

## Me
[名字]，[团队] 的 [职位]。

## People
| 谁 | 角色 |
|-----|------|
| **[绰号]** | [全名]，[职位] |

## Terms
| 术语 | 含义 |
|------|---------|
| [缩写] | [展开] |

## Projects
| 代号 | 是什么 |
|------|------|
| **[代号]** | [描述] |

## Preferences
- [发现的偏好]
```

**`memory/` 目录：**

- `memory/glossary.md` —— 完整解码表（缩写、术语、绰号、代号）
- `memory/people/{name}.md` —— 个人档案
- `memory/projects/{name}.md` —— 项目详情
- `memory/context/company.md` —— 团队、工具、流程

### 8. 汇报结果

```
效率系统已就绪：
- 任务：TASKS.md（X 条）
- 记忆：X 个人物，X 个术语，X 个项目
- 看板：已在浏览器打开

用 /update 保持更新（加 --comprehensive 做深度扫描）。
```

## 注意

- 如果记忆已初始化，这一步只是打开看板
- 绰号至关重要——一定要记下大家实际怎么称呼一个人
- 某个来源不可用时，跳过它并记录缺口
- 引导完成后，记忆会在日常对话中自然增长
