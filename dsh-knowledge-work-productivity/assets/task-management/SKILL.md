# 任务管理

任务记录在一个你和助手都能编辑的 `TASKS.md` 文件里。

> **本技能不依赖任何 MCP 连接器。** 所有操作都落在本地 `TASKS.md` 文件上，未连接 Slack / Notion / Asana / Linear / Jira / Monday / ClickUp / 日历 / Gmail 时**完整可用**。

## ⚠️ 连接器依赖

**本技能用到的服务：无。** 任务管理完全基于本地 `TASKS.md` 文件，不需要任何 MCP 连接器，所有步骤开箱即用。

- 从外部工具（Asana / Linear / Jira 等）同步任务是**另一个技能** `update` 的职责；本技能只管本地清单本身。
- 需要从对话、邮件、聊天记录里提取待办时，直接基于用户贴出的内容或 `@` 引用的文件即可，不依赖连接器。

## 文件位置

**始终使用当前工作目录下的 `TASKS.md`。**

- 如果已存在，直接读写它
- 如果不存在，用下面的模板新建

## 看板设置（首次运行）

有一个可视化看板可用于管理任务和记忆。**首次处理任务时：**

1. 检查当前工作目录下是否存在 `dashboard.html`
2. 如果不存在，把它从本技能的插件目录（`assets/dashboard.html`，即本技能所在目录的**上级** `assets/` 里）复制到当前工作目录
3. 告诉用户：「我已经把看板加好了。运行 `/start` 来把整套系统搭起来。」

这个任务看板：

- 读写同一个 `TASKS.md` 文件
- 自动保存改动
- 监听外部改动（你用编辑器改了它会自动同步）
- 支持拖拽调整任务和分区的顺序

## 格式与模板

新建 `TASKS.md` 时，用这个模板（不含示例任务）：

```markdown
# Tasks

## Active

## Waiting On

## Someday

## Done
```

任务格式：

- `- [ ] **任务标题** - 上下文、为谁、截止日期`
- 需要补充细节时用子条目
- 已完成：`- [x] ~~任务~~（日期）`

## 如何交互

**当用户问「我今天有什么事」/「我的任务」时：**

- 读 `TASKS.md`
- 总结 Active 和 Waiting On 两个分区
- 高亮任何逾期或紧急的条目

**当用户说「加个任务」/「提醒我……」时：**

- 用 `- [ ] **任务**` 格式加到 Active 分区
- 如果用户给了上下文就带上（为谁、截止日期）

**当用户说「X 做完了」/「X 搞定了」时：**

- 找到那个任务
- 把 `[ ]` 改成 `[x]`
- 加删除线：`~~任务~~`
- 加完成日期
- 移到 Done 分区

**当用户问「我在等什么」时：**

- 读 Waiting On 分区
- 注明每一项已经等了多久

## 约定

- 任务标题用**加粗**，便于扫读
- 如果是对某人的承诺，写明「给 [某人]」
- 有截止日期就写「[日期] 前」
- 等待中的条目写「自 [日期] 起」
- 补充上下文用子条目
- Done 分区保留约 1 周，然后清掉旧条目

## 提取任务

总结会议或对话时，主动提出把提取到的待办加进来：

- 用户自己承诺的事（「我把那个发过去」）
- 分派给用户的行动项
- 提到的后续跟进

**先问再加** —— 不要不经确认就自动添加。

> 提取待办时，如果内容来自聊天 / 邮件 / 文档工具，用户可以直接把文字贴给你、或用 `@` 引用导出的文件；**不需要连接这些服务的连接器**。若用户希望助手自动去 Slack / Gmail / Notion 里拉取，那属于 `update --comprehensive`（深度扫描）的范畴，需在 设置→MCP 连接对应服务；未连接时改为手动提供内容或跳过此步。
