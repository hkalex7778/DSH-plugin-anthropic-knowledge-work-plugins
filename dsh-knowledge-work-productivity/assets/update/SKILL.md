# 更新命令

> 如果遇到不认识的占位符，或想确认哪些工具已连接，见下方「⚠️ 连接器依赖」。

保持任务清单和记忆的最新。两种模式：

- **默认：** 从外部工具同步任务、清理过期条目、检查记忆缺口
- **`--comprehensive`：** 深度扫描聊天、邮件、日历、文档——标记遗漏的待办并建议新记忆

用法：

```
/update
/update --comprehensive
```

## ⚠️ 连接器依赖

本技能可能用到这些服务（按步骤标注）：

| 服务 | 用在哪一步 | 未连接时怎么办 |
|---|---|---|
| **Asana / Linear / Jira(Atlassian) / Monday / ClickUp** | 第 2 步：从项目跟踪工具拉取指派给你的任务 | 跳过自动同步，直接进入第 3 步（清理本地 TASKS.md）；或让用户手动粘贴外部任务 |
| **Google 日历 / Microsoft 365 日历** | 深度扫描：列出近期 + 即将到来的事件 | 跳过日历部分 |
| **Slack** | 深度扫描：搜索近期消息、读取活跃频道 | 改为用户手动贴聊天记录，或跳过 |
| **Gmail / Microsoft 365 邮件** | 深度扫描：搜索已发消息 | 改为用户手动贴邮件，或跳过 |
| **Notion / Microsoft 365 文档** | 深度扫描：列出最近改动的文档 | 改为用户手动提供，或跳过 |

**降级原则：** 默认模式下，**第 1、3、4、5、6、7 步完全不依赖连接器**——它们只读写本地 `TASKS.md` 与 `memory/`。只有第 2 步（外部同步）和深度扫描需要连接器。未连接时跳过这些步骤，其余 SOP 照常走完，功能降级为**半自动**（外部内容需用户手动粘贴）。

此步需在 设置→MCP 连接 `<服务名>`；未连接时改为手动提供内容/粘贴数据，或跳过此步。

## 默认模式

### 1. 加载当前状态

读 `TASKS.md` 和 `memory/` 目录。如果它们不存在，建议先运行 `/start`。

### 2. 从外部来源同步任务

检查可用的任务来源：

- **项目跟踪工具**（如 Asana、Linear、Jira）（需连接对应 MCP）
  > **连接器提示：** 此步需在 设置→MCP 连接 `<Asana / Linear / Jira>`；未连接时改为手动提供内容/粘贴数据，或跳过此步。
- **GitHub Issues**（如果在仓库里）：`gh issue list --assignee=@me`（不依赖 MCP 连接器）

如果没有任何来源可用，跳到第 3 步。

**拉取指派给用户的任务**（待办/进行中）。与 `TASKS.md` 对比：

| 外部任务 | TASKS.md 匹配？ | 动作 |
|---------------|-----------------|--------|
| 找到，但不在 TASKS.md | 无匹配 | 提出添加 |
| 找到，已在 TASKS.md | 按标题模糊匹配 | 跳过 |
| 在 TASKS.md，但外部已无 | 无匹配 | 标记为可能已过期 |
| 外部已完成 | 在 Active 分区 | 提出标记完成 |

呈现差异，让用户决定添加/完成哪些。

### 3. 清理过期条目

审查 `TASKS.md` 里的 Active 任务，标记：

- 截止日期已过的任务
- 在 Active 里待了 30 天以上的任务
- 没有上下文的任务（没写为谁、没写属于哪个项目）

逐条呈请清理：标记完成？改期？移到 Someday？

### 4. 解码任务以发现记忆缺口

对每个任务，尝试解码所有实体（人物、项目、缩写、工具、链接）：

```
任务：「把 PSR 发给 Todd，关于 Phoenix 的阻塞点」

解码：
- PSR → ✓ Pipeline Status Report（在术语表里）
- Todd → ✓ Todd Martinez（在 people/ 里）
- Phoenix → ? 不在记忆里
```

记录哪些已完全解码、哪些有缺口。

### 5. 填补缺口

把未知的术语分组呈现：

```
我在你的任务里发现一些我没有上下文的术语：

1. "Phoenix"（来自："把 PSR 发给 Todd，关于 Phoenix 的阻塞点"）
   → Phoenix 是什么？

2. "Maya"（来自："和 Maya 同步 API 设计"）
   → Maya 是谁？
```

把答案加到相应的记忆文件（people/、projects/、glossary.md）。**这一步不依赖连接器。**

### 6. 捕获富上下文

任务常常比记忆本身包含更丰富的上下文。提取并更新：

- 任务里的**链接** → 加到项目/人物文件
- **状态变化**（「上线完成」）→ 更新项目状态，从 WORKPLACE.md 降级
- **关系**（「Todd 在 Maya 的提案上签字」）→ 交叉引用人物
- **截止日期** → 加到项目文件

### 7. 汇报

```
更新完成：
- 任务：从项目跟踪工具（如 Asana）+3，完成 1，清理 2
- 记忆：填补 2 个缺口，丰富 1 个项目
- 所有任务已解码 ✓
```

## 深度扫描模式（`--comprehensive`）

包含默认模式的一切，外加对近期活动的深度扫描。

> **连接器提示：** 深度扫描重度依赖连接器。若未连接任何相关服务，本模式退化为：基于用户手动粘贴的聊天/邮件/日历内容做同样的分析，或整体跳过并告知用户。

### 额外步骤：扫描活动来源

从可用的 MCP 来源收集数据：

- **聊天：** 搜索近期消息、读取活跃频道（需连接 Slack）
  > **连接器提示：** 此步需在 设置→MCP 连接 `Slack`；未连接时改为手动提供内容/粘贴数据，或跳过此步。
- **邮件：** 搜索已发消息（需连接 Gmail / Microsoft 365）
  > **连接器提示：** 此步需在 设置→MCP 连接 `Gmail`；未连接时改为手动提供内容/粘贴数据，或跳过此步。
- **文档：** 列出最近改动的文档（需连接 Notion / Microsoft 365）
  > **连接器提示：** 此步需在 设置→MCP 连接 `Notion`；未连接时改为手动提供内容/粘贴数据，或跳过此步。
- **日历：** 列出近期 + 即将到来的事件（需连接 Google 日历 / Microsoft 365）
  > **连接器提示：** 此步需在 设置→MCP 连接 `日历`；未连接时改为手动提供内容/粘贴数据，或跳过此步。

### 额外步骤：标记遗漏的待办

把活动与 `TASKS.md` 对比。找出没有被记录的行动项：

```
## 可能遗漏的任务

从你的活动里，这些看起来是还没记录的待办：

1. 来自聊天（1 月 18 日）：
   "我周五前把更新后的原型发过去"
   → 加到 TASKS.md？

2. 来自会议「Phoenix 站会」（1 月 17 日）：
   你有一个循环会议，但没有活跃的 Phoenix 任务
   → 这里需要补什么吗？

3. 来自邮件（1 月 16 日）：
   "我这周 review 一下 API 规范"
   → 加到 TASKS.md？
```

让用户挑选要加哪些。

### 额外步骤：建议新记忆

找出记忆里还没有的新实体：

```
## 新人物（不在记忆里）
| 名字 | 频次 | 上下文 |
|------|-----------|---------|
| Maya Rodriguez | 12 次提及 | 设计、UI 评审 |
| Alex K | 8 次提及 | 关于 API 的私信 |

## 新项目/话题
| 名字 | 频次 | 上下文 |
|------|-----------|---------|
| Starlight | 15 次提及 | 规划文档、产品 |

## 建议清理
- **Horizon 项目** —— 30 天内无提及。标记完成？
```

按置信度分组呈现。高置信的条目直接提出添加；低置信的询问用户。

## 注意

- 未经用户确认，绝不自动添加任务或记忆
- 外部来源的链接在可用时予以保留
- 对任务标题做模糊匹配，容忍措辞的细微差异
- 可以频繁运行——只在新信息出现时才更新
- `--comprehensive` 始终以交互方式运行
